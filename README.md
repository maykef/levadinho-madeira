# Levadinho

**[levadinho-madeira.com](https://levadinho-madeira.com/)** — a static website answering the questions
visitors actually ask about Madeira's paid, booking-only PR hiking trails: is it open today, how much is
the ticket, how do I book, how do I get there and back. In five languages (English at the root; `pt/`,
`fr/`, `de/`, `pl/`), with a WhatsApp assistant behind it.

No framework, no build step. Every page is a self-contained `.html` (inline CSS and JS) served straight
from this repo by GitHub Pages. What keeps ~300 URLs consistent is a set of Python generators and one
daily data pipeline.

## How the site is organised

- **The hub** — `/` is a live "open or closed today?" board for all ~37 classified PR trails.
- **The spokes** — one page per trail (`/25-fontes/`, `/pico-ruivo/`, …): 9 hand-authored for the
  most-walked trails, the rest generated by `scripts/gen_spokes.py` from the official sources. Each has a
  live status card, a facts table, bus connections and a trailhead map.
- **The guides** — answer pages for the real queries: fees, SIMplifica booking (and from abroad),
  "do I need a permit", getting back from the one-way PR1, sunrise transport, Areeiro parking and weather,
  best/easy/tunnel levadas, free walks, levadas by bus, Funchal today, cruise-port day plans
  (one day / two days in Madeira, Monte, the short PR1 walk to Pedra Rija).

## The daily pipeline

`scripts/update_status.py` runs once a day via GitHub Actions (`.github/workflows/update.yml`):

1. Scrapes the **official IFCN trail-warnings list** — the only authoritative source for closures — and
   maps its sections to OPEN / PARTIAL / CLOSED per trail, keeping IFCN's own note.
2. Reads **measured IPMA weather** for the summit and five regions (open data; implausible values are
   rejected rather than published).
3. Writes `status.json` (which `status.js` / `dashboard.js` render client-side), refreshes the static
   crawlable status lines embedded in every page, updates `sitemap.xml` lastmod only for pages whose
   content really changed, and regenerates the machine-readable editions: `llms.txt`, `llms-full.txt`,
   the `trail-status.xml` RSS of status changes and the daily `history/status-daily.jsonl`.
4. Commits only if something changed. A failed scrape fails the run: yesterday's honest data stays live
   instead of garbage.

Prices and timetables printed on the pages come from the operators' and the Region's own publications
(Portarias, SIMplifica, Horários do Funchal, the attractions' sites) and are re-checked daily by
`scripts/check_prices.py`; every page carries a disclaimer asking readers to confirm before buying.

## The generators (`scripts/`)

Pages are never hand-edited inside generated markers. Each concern has one idempotent script: site nav and
breadcrumbs (`gen_site_nav.py`), the WhatsApp block (`gen_cta.py`), footer and schema (`gen_owner.py`,
`gen_schema.py`), bus sections (`gen_bus.py`), webcams, answer cards, QR codes, the AI feeds, and one
generator per guide page. Changing copy means changing the generator and re-running it.

## The WhatsApp bot (`bot/`) and knowledge backend (`backend/`)

Levadinho the assistant answers on WhatsApp and on-page web chat, grounded exclusively in the knowledge
store (`backend/`, Postgres) built from these pages, the official fact files and the live `status.json` —
it may not state facts from anywhere else. The bot's source is public here; its credentials, logs and
analytics are not (see `.gitignore`). Privacy policy: [/privacy/](https://levadinho-madeira.com/privacy/).

## Facts discipline

Every price, rule and date on the site traces to an official source (IFCN, SIMplifica, Visit Madeira,
the Portarias, IPMA, the transport operators) or to first-hand verification on the island. Where sources
conflict, the page says so or stays silent. No visible "last updated" dates: freshness is shown by being
right, not by a timestamp.
